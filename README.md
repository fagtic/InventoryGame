**Вариант 4. Инвентарь ролевой игры**
Консольное приложение (C# / .NET 8), демонстрирующее древовидный инвентарь персонажа: одиночные предметы и вложенные контейнеры обрабатываются одинаково, поддерживается подсчёт суммарного веса и стоимости, а также быстрое клонирование предметов по образцу.

**Использованные паттерны**
Composite
Проблема. В инвентаре есть одиночные предметы (меч, зелье) и контейнеры (сумка, сундук), которые могут лежать друг в друге. Без паттерна пришлось бы в каждом месте писать if (item is Container) { foreach (...) ... } и дублировать логику подсчёта веса/стоимости и обхода.

**Решение. **Общий интерфейс IInventoryItem реализуют и Item (лист), и Container (узел). Container хранит List<IInventoryItem> и рекурсивно вызывает Weight, Price, Display у детей — клиенту всё равно, с чем он работает.

**Без паттерна. **Дублирование обхода во всех местах, где нужно «посчитать вес всего» или «показать дерево», и хрупкость при добавлении нового типа контейнера.

**Prototype**
**Проблема.** Игровой код часто создаёт «ещё один такой же меч», не зная конкретного класса. Если клонировать вручную (new Sword(...)), клиент зависит от всех конкретных классов и должен знать все поля.

**Решение.** Интерфейс IInventoryItem наследует ICloneable и объявляет Clone(). Item.Clone() создаёт экземпляр через конструктор, а Container.Clone() делает глубокую копию (клонирует каждого ребёнка). Реестр ItemRegistry хранит образцы по ключу и по запросу возвращает копию.

**Без паттерна. ** При добавлении нового типа предмета пришлось бы править все места создания копий; глубокое копирование дерева руками легко ошибить.
